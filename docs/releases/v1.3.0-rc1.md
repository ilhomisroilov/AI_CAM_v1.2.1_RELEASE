# AI_CAM v1.3.0-rc1 — Reliability & OCR Dataset Overhaul (Release Candidate)

Release candidate on `release/v1.3.0-reliability`. **Production `master` is
untouched.** This is a candidate: promotion to final `v1.3.0` requires the 24-hour
production observation to pass on the Ubuntu GPU host (not run in this build).

## Highlights
- **PLC forensic audit** of D2222 — debounced rising/falling timeline with
  pulse-width, inter-edge interval, ring-buffer context and per-edge decision
  (`runtime/audit/plc_edges_*.csv/jsonl`).
- **Production body-cycle invariant** — 1 body = 1 cycle = 1 record. Triggers during
  an active cycle → `DUPLICATE_TRIGGER_IGNORED`; sooner than 90 s →
  `SUSPICIOUS_EARLY_TRIGGER`; both audited. No pending-trigger queue in production.
- **Strict YOLO ≥ 0.90 OCR gate** — `best_q` can no longer override detector
  confidence.
- **Three-engine OCR evidence** stored separately; **F/E · U/V disagreement audit**;
  **weak-position false-positive guard** (independent frames, not preprocess
  variants); **VIN_LOCKED** cancels retries after an accepted VIN.
- **Dataset character alignment** — engraved boxes / adaptive projection preferred;
  equal-width split is never production training-eligible (→ `PENDING_REVIEW`).
- **Failure-evidence images** — a decoded-but-no-VIN cycle always has an image.
- **`tools/observe_production.py`** + `run.py --observe-hours N` — real 24h
  observation and report generator (never mocked, never faked).

## Run
```bash
cd AI_CAM
python3.11 -m venv .venv && source .venv/bin/activate
python -m pip install --upgrade pip wheel setuptools
pip install --no-deps paddleocr==2.10.0
pip install -r requirements-linux.txt
python tools/install_runtime.py --profile gpu
python run.py --self-check --require-gpu
python run.py
# then, for the acceptance gate:
python run.py --observe-hours 24
```
